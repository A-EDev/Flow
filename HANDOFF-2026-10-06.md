## 2. What changed, by area

Detailed rationale is in `BUGFIX-AUDIT-2026-10-06.md`. Summary:

### Video playback (correctness)
- `player/sabr/integration/SabrSegmentBuffer.kt` — removed a CPU busy-spin on ExoPlayer's
  loading thread when a non-blocking poll came back empty.
- `player/EnhancedPlayerManager.kt` — cancel autoplay countdown on `stop()`/`clearCurrentVideo()`;
  release the advance wake lock on clear; cancel `autoplayJob`/`eqObserver` on `release()`;
  preserve `playWhenReady` on audio-track and quality reloads (they used to start playback while
  paused).
- `player/sabr/core/SabrSessionState.kt`, `player/sabr/integration/SabrOrchestrator.kt`,
  `player/sabr/integration/SabrDownloadEngine.kt` — cross-thread visibility: `@Volatile` scalars
  and an `AtomicInteger` error counter.
- `player/sabr/proto/ProtobufReader.kt` — bounds checks (truncated varints/fixed fields,
  negative/oversized length-delimited fields).

### Video player UI / performance
- `ui/screens/player/stage/FullscreenSidePanel.kt`, `ui/screens/player/VideoPlayerHost.kt`,
  `ui/screens/player/stage/SponsorSkipLayer.kt` — the fullscreen side drawer read its animated
  offset in composition, recomposing the whole player host every frame of the tween/drag. Moved
  to layout-phase providers + `Modifier.layout` / `Modifier.offset { }`. Arithmetic unchanged
  (pixel-identical).
- `ui/components/videoplayer/controls/PlayerScrubController.kt` — scrub settle now polls the
  playhead via `snapshotFlow` instead of reading it in composition.
- `ui/components/videoplayer/controls/PlayerControlsOverlay.kt` + `PlayerLockedControls.kt` —
  the lock-mode LIVE dot is now gated on layer visibility (was an infinite animation in a
  warm-but-unplaced layer).
- `ui/components/videoplayer/gesture/PlayerTapGestures.kt` — forward double-tap no longer seeks
  to 0 while duration is unknown.
- `ui/components/videoplayer/gesture/PlayerDragGestures.kt` — cancel the 500 ms HUD-hide timer on
  a new gesture (removed a mid-gesture flicker race).
- `ui/components/videoplayer/UpcomingVideoOverlay.kt` — premiere countdown gated on
  `repeatOnLifecycle(STARTED)` and bounded at expiry.
- `ui/components/musicplayer/queue/QueueTrackRow.kt` — confined the per-frame swipe read to the
  reveal panel; the row now recomposes only when the swipe settles.

### DLNA / casting
- `player/dlna/DlnaCastManager.kt` — `stopDiscovery()` now stops the proxy server when no cast is
  active (it was leaking a bound `ServerSocket` for the process lifetime after dismissing the
  picker).
- `player/dlna/StreamProxyServer.kt` — close the OkHttp response in `finally` (was leaking on a
  mid-stream error).

### Downloads / storage
- `data/video/storage/DownloadFiles.kt` — delete a partial target when a cross-filesystem move
  fails (was leaving an orphan in the user's chosen folder).

### Data / network / recommendation
- `data/recommendation/NeuroStorage.kt` — persist `TopicEvidence.negativeSignals` (was silently
  reset to 0 on every restart, so repeatedly-disliked topics were re-surfaced as "exploration").
- `data/repository/SponsorBlockRepository.kt`, `data/repository/DeArrowRepository.kt` — cache
  one `OkHttpClient` keyed by `AppProxyManager.currentSignature()` instead of building one (with
  its own pool/dispatcher) per request.
- `data/recommendation/FlowNeuroEngine.kt` — synchronize the three `featureCache.clear()` calls
  with the already-guarded get/put.
- `innertube/pages/NewPipe.kt` — `@Synchronized` on `init()` / `invalidateClient()`.

### Non-player UI / notifications
- `notification/ReminderReceiver.kt` + `res/values/strings.xml` — moved the receiver's DataStore
  I/O off the main thread via `goAsync()` + IO, and moved hardcoded reminder strings to
  `strings.xml`.
- `ui/screens/sync/SyncSessionContent.kt` — bound the QR expiry countdown.
- `ui/screens/sync/QrComponents.kt` — unbind the camera and shut down the analyzer executor on
  dispose; guard the provider listener against late resolution.
- `ui/screens/shorts/ShortsScreen.kt`, `ui/screens/channel/ChannelScreen.kt` — use
  `collectAsStateWithLifecycle()`.
- `data/local/QueuePersistence.kt` — dirty-check the 30 s auto-save so an idle app stops
  rewriting identical DataStore data.

### Reverted (tests pin the current behaviour as intended)
- `player/sponsorblock/SponsorBlockHandler.kt` — changing the `!isEnabled && !offlineSegmentsLoaded`
  gate to require `isEnabled` broke 4 tests; offline/on-device segments are meant to apply
  regardless of the online toggle. **Its doc comment is misleading and should be corrected.**
- `data/video/downloader/work/DownloadController.kt` — `KEEP` → `APPEND_OR_REPLACE` broke
  `DownloadControllerTest`, which asserts `KEEP`.

## 3. Pending work (prioritised)

Full context and recommended fixes are in `BUGFIX-AUDIT-2026-10-06.md` §"Identified but not
changed".

### P1 — security / resource exposure
1. **DLNA proxy binds `0.0.0.0` with no auth and no real connection cap**
   (`player/dlna/StreamProxyServer.kt`). `MAX_CONNECTIONS` is only the `ServerSocket` backlog.
   Decide: bind to the Wi-Fi address + enforce a concurrent-connection limit.
2. **`StreamProxyServer.start()` race** can leak a bound socket (guard set after socket creation,
   inside the coroutine). Make start synchronous under a lock.

### P2 — playback/download correctness (needs device or live traffic)
3. **`RangeDownloader` accepts HTTP 200 for googlevideo without verifying `Content-Range`** start
   (`data/video/downloader/transfer/RangeDownloader.kt`). Either verify or require 206.
4. **Download resume discarded when a format has no `contentLength`** — `TransferState.restoreInto`
   compares a pre-probe `0L` to the saved size, so pause/lost-network restarts the file.
5. **`CustomMediaCodecVideoRenderer` forces the `setOutputSurface` workaround for every codec**
   (`player/renderer/`). Undocumented; likely deliberate for specific devices. Needs device
   testing before narrowing.
6. **`registerHlsCast` fallback returns a video-only googlevideo URL** with an
   `application/vnd.apple.mpegurl` content type → silent video if the proxy isn't running.
7. **SABR `contentLength` checked before decompression** (`SabrStreamController`) — would drop
   gzip/brotli segments.
8. **SABR `SabrSessionState` collections** (`sabrContexts`, `sabrContextsToSend`, buffered ranges)
   still mutated from several coroutines without synchronization (only scalars fixed).
9. **`UmpFrameDecoder` has no maximum part size** — a corrupt length varint buffers unbounded
   memory.
10. **`DlnaCastManager.disconnect()` races a fast reconnect** (device nulled / polling cancelled
    only after an up-to-8 s SOAP call).
11. **Live-chat poll timeout clamped to ≤1.5 s**, overriding YouTube's 5–10 s server interval.

### P3 — architecture / wiring
12. **SponsorBlock MUTE / SHOW_TOAST emit flows with no consumer.** Needs a volume/preview-state
    design so a user's volume is restored correctly.
13. **`SleepTimerManager`** is a process-wide singleton that never calls `detachPlayer()` and
    retains Activity-capturing callbacks.
14. **`FeedInvalidationBus.emit`** uses `tryEmit` (8-slot buffer, no replay) → invalidation events
    can be dropped.
15. **`EqualizerViewModel.onCleared`** resets the shared singleton repository's bypass/preview
    while the shell holds a second, activity-scoped instance.
16. **`NotificationHelper`** still uses `runBlocking` on other call paths (only the receiver path
    fixed).
17. **`DownloadController` `KEEP` race** — a row queued as a drain finishes can stay `PENDING`
    until the user opens Downloads. A policy-neutral fix re-checks for queued rows after
    `drain()` inside `DownloadQueueWorker`.

### P4 — cleanup
18. `QueuePersistence` 30 s auto-save timer (now dirty-checked) may be removable entirely; confirm
    position persistence across process death is adequate first.
19. Correct the misleading `loadSegmentsFromList` KDoc about the disabled-toggle behaviour.
20. **No tests were added** for any of the applied fixes, and the two Compose refactors plus the QR
    camera lifecycle change are not device-verified.

## 4. Observations about the codebase

- **Mature engineering hygiene.** Most of the "classic" Compose performance regressions are
  already fixed: warm hidden layers (fullscreen player sheet, mini player, lyrics) are gated,
  position cadence is refcount-controlled, fan-out is bounded by semaphores/chunking, and
  ViewModels with expensive `init` are activity-scoped. The remaining issues were genuine
  leftovers, not widespread sloppiness.
- **The AGENTS.md constraints are load-bearing, not aspirational.** The two strongest findings
  (drawer per-frame recomposition, queue-row per-frame read) are exactly the rule the doc calls
  non-negotiable, and fixing them required moving reads to the layout phase.
- **The test suite encodes intent.** Two plausible-looking fixes were wrong: SponsorBlock
  offline-segment gating and `ExistingWorkPolicy.KEEP`. Always run
  `:app:testGithubDebugUnitTest` before trusting a "correctness" fix in this repo.
- **Recurring bug shapes found:** plain cross-coroutine `var`s in the SABR path; per-request
  `OkHttpClient` construction; unsynchronized access to a guarded map; `runBlocking` on a
  receiver path; resource cleanup (sockets/executors/responses) on error paths only.
- **Subagent findings need verification.** A few claims were overstated or wrong (e.g. a reported
  `SabrOrchestrator` scope leak — it does cancel its scope; the SponsorBlock-disabled gate is
  intended). Treat every report as a lead, not a fact.
- **Player-path changes are genuinely high-risk** per the project's own rules. The autoplay,
  `playWhenReady`, and SABR edits here touch that path and deserve real device time
  (background playback, queue advance, audio-only, PiP, process recreation).
- **graphify** is now built (26,274 nodes). `graphify explain <symbol>` was useful for confirming
  blast radius; `graphify query` is keyword-BFS and returns library-composable noise, so narrow
  the query or use `explain`/`path`.
- **graphify reported 15 files with partial extraction** (syntax warnings), including
  `innertube/YouTube.kt`, `player/audio/AudioSessionRegistry.kt`,
  `data/sponsordetection/OnDeviceSponsorDetector.kt`. Unrelated to this pass, but worth a glance —
  it may be an extractor limitation or a real parse oddity.
- **Build environment:** Gradle 9.6.1, JDK 21, configuration cache is on; always use
  flavor-prefixed tasks (`:app:assembleGithubDebug`, `:app:compileFossDebugKotlin`).
- **Perf claims are unverified by measurement here.** Everything is reasoned/compile/unit-tested;
  no frame counts, fetch counts, or benchmarks were run. Do not describe these as measured
  improvements without a device.
